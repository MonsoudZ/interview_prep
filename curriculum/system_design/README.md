# System design workspace contract

Reliable Webhook Delivery v2 retains the published load/durability/retention/fairness assumptions and adds a native canvas alongside written reasoning. The library selects v2 for new sessions; immutable v1 notes-only attempts remain supported. Time and difficulty are editorial practice estimates, not cohort-calibrated measures.

The diagram begins empty. Components represent clients, services, databases, queues, caches, and external systems. Each has a name, responsibility, position, and stable ID. Directed connections reference existing components and carry a label. Add, select, rename, describe, move, connect, and remove through the UI. Removing a component also removes incident connections. Drag or arrow keys move a focused component; Shift increases the step. Drag blank canvas to pan; fit/zoom change only the view. Architecture undo/redo is local to the mounted workspace; notes have file-local editor history. Reload restores persisted content, rather than browser-local source/history.

Six Markdown documents hold requirements/assumptions, capacity estimates, APIs/data, reliability/operations, tradeoffs, and a handoff. No automated calculation is presented as the candidate's reasoning. The diagram plus all six notes documents save atomically as one source snapshot. Autosave, save-on-navigation, optimistic conflicts, owner scoping, server deadlines, and immutable submissions use the existing platform lifecycle. Export SVG/JSON and combined Markdown represent the current tab's work; Save confirms server persistence.

`diagram.json` version 1 contains exactly version/nodes/edges. The server and browser reject unknown properties/kinds, duplicate IDs (including across components/connections), dangling/self connections, nonfinite/out-of-range positions, empty component names, and excess counts/text. Bounds: 50 components, 100 connections, coordinates 0–4000, component name 80 characters, responsibility 1,000, connection label 120, diagram source 512 KiB, all editable artifacts 1 MiB. Supported paths are fixed; all notes and the diagram must remain present. Raw SVG/HTML, embedded media, and external resources are not diagram fields. Text is escaped during SVG rendering/export; the static review preview requires no inline style or script.

Submission freezes the graph and notes together. Review shows a diagram generated from the submitted snapshot and accepts evidence references to preserved Markdown or diagram JSON lines. Ratings remain explicit self-assessment. A diagram does not prove durable acceptance, safe retries, tenant isolation, correct estimates, or senior judgment merely because a particular component appears. Voice, a conversational interviewer, calibrated automated reviews, freehand drawing, collaborative editing, image upload, layout routing, and reference architecture libraries remain future work.

Verification covers model/history/export behavior, schema validation, full-source persistence, stale-save rejection, submission/deadline locking, preserved review evidence, owner isolation, and v1 compatibility. Browser QA exercises component/connection editing, dragging/keyboard movement, undo/redo, pan/zoom, notes switching, reload/resume, real SVG/Markdown downloads, and submission/review. See `apps/platform/VERIFICATION.md` for current counts and artifacts.
